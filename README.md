# CampusFix

A campus facilities issue-tracking platform: students report issues, staff
resolve them, admins manage the whole operation.

## Structure

```
CampusFix/
├── frontend/    Phase 1-6 React (Vite) app — Student/Staff/Admin portals
└── backend/     Phase 7 Express + MongoDB API
```

## Phase 7 — what changed

The frontend's mock service layer (`frontend/src/services/*.js`,
`frontend/src/context/AuthContext.jsx`) now talks to a real backend
instead of in-memory arrays that reset on page reload:

- Real JWT authentication (`backend/src/controllers/authController.js`)
- Issues, votes, comments, and activity persisted in MongoDB
- Server-side role authorization on every protected route — not just
  frontend route guards
- Notifications generated by real backend events (assignment, status
  change, new comment, new upvote)

Only 6 frontend files were modified to wire this up:
`services/api.js` (new), `services/authService.js`, `services/issueService.js`,
`services/adminService.js`, `context/AuthContext.jsx`, and one call-site fix
in `pages/student/IssueDetails.jsx` (a synchronous mock lookup had to become
an awaited API call). No UI, styling, or component structure was changed.

## Running it locally

```bash
# Backend
cd backend
npm install
cp .env.example .env      # then edit MONGODB_URI / JWT_SECRET
npm run seed               # optional — creates demo accounts + sample issues
npm run dev                 # http://localhost:5000

# Frontend (separate terminal)
cd frontend
npm install
cp .env.example .env        # VITE_API_URL defaults to http://localhost:5000/api/v1
npm run dev                  # http://localhost:5173
```

See `backend/README.md` for the full API reference and demo credentials.

## Known scope boundaries (documented, not oversights)

- Department and issue-category management remain frontend-only mock data
  — there's no backend model for them yet. Students and Staff directories
  ARE real (`GET /users`).
- The "attach an image" field in Report Issue still only creates a local
  browser preview URL (never actually uploads a file) — this was already
  true in the Phase 1-6 mock (see `ImageUpload.jsx`'s own comments) and
  wasn't in Phase 7's scope to change.
